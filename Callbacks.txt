
When dealing with multiple Retrofit network requests in Android Kotlin, especially when you need to associate a specific callback with each request, you can achieve this by creating a custom callback interface that includes an identifier. This allows you to differentiate between the responses of various requests within a single onResponse or onFailure implementation.
Here's how you can implement this: Define a Custom Callback Interface.
Create an interface that extends Retrofit's Callback and adds an id parameter to its methods.
Kotlin

    interface MyCustomCallback<T> : Callback<T> {
        fun onResponse(call: Call<T>, response: Response<T>, requestId: Int)
        fun onFailure(call: Call<T>, t: Throwable, requestId: Int)
    }
Modify Your Retrofit Service Interface.
Your Retrofit service interface methods will still return Call<T>.
Kotlin

    interface ApiService {
        @GET("data/{id}")
        fun getData(@Path("id") id: Int): Call<MyData>
    }
Implement and Use the Custom Callback.
When making your network requests, you can create instances of your MyCustomCallback and pass in the requestId.
Kotlin

    // In your Activity, Fragment, or ViewModel
    val apiService = RetrofitClient.instance.create(ApiService::class.java)

    // Request 1
    apiService.getData(1).enqueue(object : MyCustomCallback<MyData> {
        override fun onResponse(call: Call<MyData>, response: Response<MyData>, requestId: Int) {
            if (response.isSuccessful) {
                val data = response.body()
                // Handle data for requestId 1
            } else {
                // Handle error for requestId 1
            }
        }

        override fun onFailure(call: Call<MyData>, t: Throwable, requestId: Int) {
            // Handle failure for requestId 1
        }
    }, 1) // Pass the ID for this request

    // Request 2
    apiService.getData(2).enqueue(object : MyCustomCallback<MyData> {
        override fun onResponse(call: Call<MyData>, response: Response<MyData>, requestId: Int) {
            if (response.isSuccessful) {
                val data = response.body()
                // Handle data for requestId 2
            } else {
                // Handle error for requestId 2
            }
        }

        override fun onFailure(call: Call<MyData>, t: Throwable, requestId: Int) {
            // Handle failure for requestId 2
        }
    }, 2) // Pass the ID for this request
Important Considerations:
Error Handling:
Ensure you handle both successful responses (response.isSuccessful) and error responses within onResponse, as well as network failures in onFailure.
Context:
Be mindful of potential memory leaks if your callbacks hold strong references to Activity or Fragment contexts. Consider using WeakReference or ensuring the lifecycle of your callback aligns with the component.
Kotlin Coroutines:
For more complex scenarios or to avoid "callback hell," consider using Kotlin Coroutines with Retrofit. This allows for a more sequential and readable way to handle asynchronous operations. Retrofit provides suspend functions that can be directly called from coroutines, simplifying error handling and result processing.
